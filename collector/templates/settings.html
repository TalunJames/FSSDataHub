The schedule

Scope and politeness

Links are only followed when their address or link text matches a keyword, and a fetched page only gets stored and read by the AI when its content does too. Documents (PDF, CSV, XLS) always pass both tests.

{% if settings.search_api_key_set %}{% endif %}

Without a key the crawler scrapes public result pages, which get throttled and blocked. When that happens the run says so rather than reporting an empty result as if it were an answer.

The query ceiling is for the whole app, not per worker: auto is 60 a minute with a key and 12 without. An engine that starts refusing is benched with escalating backoff while the next one answers, so a throttle costs coverage rather than quietly returning nothing. Without a key this is the real limit on how fast the database fills — at about five queries a place, twelve a minute is roughly two places a minute however many run at once.

Fetch engine

Almost all of a place is spent waiting on a web server and then on the AI, so places at once is the dial that decides whether a full run takes weeks or months. It does not make us less polite: seconds between requests is a ceiling on the whole app and the budget is divided among them, so raising this never increases the load on any one county's server. Past about four, set a Brave Search key — scraped result pages are what gives out first.

Batch reading

Only used when reading in batches is on, above.

A short queue is sent anyway when nothing else is in flight, so the last few places in a run are not left waiting. Fetching a finished batch is one download, but filing each result means a double-check apiece, so filing is metered to keep a finished batch from stalling the crawl.
