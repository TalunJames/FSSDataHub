Settings

The collector runs without any of this once a provider key is set. Keys stay in the SQLite file on your dataset.

Running on its own

With autopilot on, nobody has to choose what to research. It sets up the database, loads the free national files, works out each state's rules, then works through counties and cities in population order and re-checks records as they age.

Setting re-check days to 0 turns refreshing off. Items that run out of tries move to stuck on the work list instead of cycling forever.

Extractor

none archives pages only. llama talks to a local Ollama (or llama.cpp) server. openai also accepts any OpenAI-compatible base URL (LM Studio, Groq, vLLM). Anthropic defaults to Sonnet for extraction; the system prompt is prompt-cached.

OpenAI-compatible
Anthropic

claude-sonnet-5 is the recommended extractor. claude-haiku-4-5 is the budget option; claude-opus-5 the deepest reader.

Local Llama / Ollama

On TrueNAS, use the Ollama app’s IP or host.docker.internal:11434 if Ollama runs on the host.

Second checker

A second AI pass reviews every extraction: does the quoted source support the number, is it this jurisdiction's own rate, does the unit make sense. Items that pass are marked complete automatically — you only review what gets flagged.

With Anthropic, claude-haiku-4-5 keeps checking cheap. If the checker is off or cannot run, everything goes to human review — it never fails toward trust.

When it runs

Scope & politeness

Without a key the crawler scrapes public result pages, which get throttled and blocked. When that happens the run says so rather than reporting an empty result as if it were an answer. auto uses the key when one is present.

Fetch engine

Seconds between requests above still caps the rate; Crawlee spends that budget across hosts instead of idling between single fetches.

Do it by hand

Only needed to jump the queue: research a particular state now, or re-pull a bulk file.
